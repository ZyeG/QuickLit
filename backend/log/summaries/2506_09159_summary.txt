MOSE: A Novel Orchestration Framework for Stateful Microservice Migration at the Edge
INTRODUCTION: Motivates the need for stateful microservice migration at the edge to sustain low-latency services for mobile users and outlines key challenges in implementation and orchestration. Introduces MOSE, a framework that preserves connections, is application- and platform-agnostic, and reduces migration downtime substantially, demonstrated on two realistic use cases.

RELATED WORK: Reviews stateless vs. stateful migration and prior efforts on minimizing disruption and enabling connection handover. Highlights limitations of existing approaches (e.g., client code changes, kernel/protocol modifications, centralized proxies) and positions MOSE as the first to jointly address efficient stateful migration and transparent connection preservation at edge scale.

PRELIMINARIES: USED TECHNOLOGIES: Describes stateful container migration with CRIU and Podman and contrasts Cold Migration with Iterative PreCopy. Presents COAT, an overlay-network method to migrate active connections transparently, and PAM, an analytical model that upper-bounds migration duration and downtime to guide configuration.

THE MOSE FRAMEWORK: Details an architecture with an orchestrator and agents on edge hosts and clients, communicating via the low-latency Zenoh protocol. The agent implements COAT and configures OvS; the orchestrator includes profiling, metrics aggregation, a migration designer, a scheduler, and a network controller. Using PAM, the migration designer selects strategy (Cold/PreCopy/Iterative PreCopy), bandwidth, and number of iterations to meet KPI targets under different vertical objectives. A protocol flow automates signaling, checkpoint transfer, overlay reconfiguration, and restoration without SSH tunnels, keeping applications unmodified.

EXPERIMENTAL TESTBED AND MOSE’S VALIDATION: Uses a four-VM OpenStack testbed and two stateful microservices (SockPerf, iPerf3) to compare MOSE against state-of-the-art baselines. MOSE cuts step times from seconds to sub-seconds and reduces downtime by up to 77%, while preserving established connections. Results validate PAM’s predictions as safe upper bounds and show effective orchestration in both downtime-minimizing (MOSE-MD) and resource-minimizing (MOSE-MR) modes. The framework automates discovery and control, simplifying deployment and improving scalability.

MOSE FRAMEWORK EXPLOITATION: Demonstrates MOSE on a UAV autopilot service and a multi-object tracking pipeline (Ultralytics YOLOv8 + BoT-SORT) streamed from a UAV. For the autopilot, MOSE lowers downtime and UAV trajectory error (up to 97% reduction) and can cut required bandwidth when targeting resource efficiency. For tracking, MOSE prevents over-provisioning (up to 91% bandwidth reduction), meets KPI targets across model sizes, and supports probabilistic planning when link capacity varies. Overall, MOSE selects strategies/parameters that align with targets and workload complexity without modifying applications.

CONCLUSIONS: Presents MOSE as a practical, general solution for stateful microservice migration at the edge that preserves connections and orchestrates migrations to meet QoE targets. Experiments and use cases show large gains in downtime, accuracy-related impact, and resource usage, indicating suitability for reliability-critical, time-sensitive edge applications.
